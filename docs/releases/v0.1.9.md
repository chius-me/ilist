# ilist v0.1.9

## Feature release after v0.1.8 security hardening

This release ships the post-v0.1.8 product slices:

- **Upload resume after reload.** `GET /api/admin/uploads/sessions` lists unfinished multipart sessions for the administrator. The UI restores them and requires re-selecting the original local file before parts continue. Cancel still aborts the server session. Native R2 binding uploads at or above `10 MiB` are rejected with `UPLOAD_SESSION_UNSUPPORTED` instead of failing only at the platform body limit.
- **Share download limits and token rotation.** Shares may set `maxDownloads`. Download counters increment atomically on public download. `POST /api/admin/shares/:id/rotate` issues a new public URL and invalidates the previous token while preserving policy. Access counters increment on public metadata/list paths.
- **Server-side directory name filter.** `GET /api/fs/list?q=` filters entry names after listing so discovery is not limited to client-side filtering of an already-loaded page.
- **Same-mount copy.** `POST /api/admin/entries/copy` copies within one mount and rejects destination name conflicts (aligned with v0.1.8 no-overwrite). Batch partial failures surface per-item codes and messages.
- **Sandboxed PDF preview and bounded text preview.** PDF is still an attachment by default. Explicit `preview=1` serves PDF inline under the existing file CSP sandbox; the UI embeds it in a sandboxed iframe. Text preview fails closed above `512 KiB`.

## Deployment order

1. Export the remote D1 database outside the repository:

   ```bash
   npx wrangler d1 export ilist-db --remote --output /tmp/ilist-db-before-v0.1.9.sql
   ```

2. Apply all remote D1 migrations before deploying the Worker:

   ```bash
   npx wrangler d1 migrations apply ilist-db --remote
   ```

   This release adds `0018_share_limits_and_counters.sql` (`download_count`, `max_downloads`, `access_count`). Existing shares keep zeroed counters and unlimited downloads unless an administrator sets a limit.

3. Deploy the Worker and Assets together:

   ```bash
   npm run deploy
   ```

4. Smoke-test:

   - Start a multipart upload, reload the admin UI, re-select the same file, and confirm remaining parts complete.
   - Create a share with `maxDownloads = 1`, download once, confirm the second download is rejected.
   - Rotate a share token and confirm the old `/s/:token` URL returns not found.
   - Search a folder with `q=` and confirm server-filtered results.
   - Copy a file to another folder on the same mount and confirm name conflicts return `ENTRY_NAME_CONFLICT`.
   - Preview a PDF inline; confirm HTML/SVG remain forced downloads.

## Emergency abort and rollback

Keep migration `0018` applied; it is additive. Prefer fix-forward. Rolling the Worker back to v0.1.8 keeps the new columns but removes UI/API for limits and rotation.
