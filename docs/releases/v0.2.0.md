# ilist v0.2.0

## Dropbox storage and a more polished interface

This release promotes Dropbox to a first-class ilist storage backend and rolls up the frontend design-system and reliability work completed since v0.1.9.

### Highlights

- **Complete Dropbox storage driver.** Browse, inspect, download, upload, create folders, rename, move, copy, and delete Dropbox files and folders through the same virtual filesystem used by the existing providers.
- **Secure Dropbox OAuth.** The authorization-code flow uses PKCE, offline refresh tokens, encrypted credential storage, refresh locking, exact-origin callback validation, and provider-safe error normalization.
- **Resumable Dropbox uploads.** Large uploads use Dropbox upload sessions with ilist's existing 10 MiB sequential parts, encrypted server-side state, retry support, and best-effort provider session closure on abort.
- **Dropbox-native behavior.** Range downloads, exportable cloud files, paginated listings, stable Dropbox IDs, optional subtree roots, folder copy, and conflict-preserving writes are supported.
- **Storage administration.** Dropbox mounts can be created, connected, reconnected, disconnected, enabled, published, and mounted at a custom top-level path from the bilingual administration UI.
- **Frontend design system.** Shared visual primitives, responsive administration layouts, clearer states, and more consistent interactions improve the desktop, tablet, and mobile experience.
- **UI reliability fixes.** Explorer dialogs, overlays, focus restoration, deferred notices, publication flows, folder pickers, shares, and responsive actions received broad audit-driven fixes.

## Upgrade and deployment

No new D1 migration is introduced between v0.1.9 and v0.2.0. Existing additive migrations remain compatible.

1. Pull the release and install the locked dependencies:

   ```bash
   git checkout v0.2.0
   npm ci
   ```

2. To enable Dropbox, create a scoped Dropbox API app, enable the permissions below, and register the exact callback URL described in [Dropbox setup](../dropbox-setup.md):

   - `files.metadata.read`
   - `files.metadata.write`
   - `files.content.read`
   - `files.content.write`

3. Set the Dropbox app key and secret on the production Worker:

   ```bash
   npx wrangler secret put DROPBOX_CLIENT_ID
   npx wrangler secret put DROPBOX_CLIENT_SECRET
   ```

4. Keep `PUBLIC_ORIGIN` set to the exact HTTPS origin and keep `CREDENTIAL_MASTER_KEY` stable. The latter encrypts saved OAuth credentials, OAuth state, and resumable-upload state.

5. Deploy the Worker and Assets together:

   ```bash
   npm run deploy
   ```

## Smoke test

- Create a Dropbox mount with an empty root folder ID and finish the authorization redirect.
- Confirm the mount reports connected and lists the Dropbox root.
- Upload a small file, download it, rename it, move or copy it into a folder, then delete it.
- Start a multipart upload and confirm pause/resume or retry completes successfully.
- Verify the storage manager and explorer remain usable at desktop, tablet, and mobile widths.

Dropbox apps in Development status are limited to their enabled development users. Apply for Dropbox production status before offering authorization to general users.

## Rollback

This release has no new schema migration. Prefer fix-forward; if rollback is required, redeploy v0.1.9. Dropbox mount rows and encrypted credentials remain inert to v0.1.9 and can be used again after returning to v0.2.0.
