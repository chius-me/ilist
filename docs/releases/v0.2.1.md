# ilist v0.2.1

## Per-mount credentials, iList chrome, and OneDrive roots

This release rolls up the work after v0.2.0: OAuth application credentials can be stored on each mount, the public product name is **iList**, OneDrive accepts an optional root folder, and the explorer chrome bugs around language, search, sort, and listing height are fixed. The short-lived PikPak driver is retired.

### Highlights

- **Per-mount OAuth credentials.** OneDrive, Google Drive, and Dropbox mounts store their own client ID and secret from `/admin/storages`. Existing Worker secrets remain a fallback for mounts that have not been migrated.
- **OneDrive Root folder ID.** Create and edit accept an optional Graph item ID, the same way Google Drive and Dropbox already do. Blank mounts the OneDrive drive root.
- **User-facing iList name.** Site header, document title, and product copy use `iList`. Package, Worker, D1, R2, cookies, and hostnames stay `ilist`.
- **Explorer chrome.** The language control shows a single horizontal `EN` / `中`. Search expands left from the toolbar control instead of flashing into the path slot. Sort labels (`Name` / `Size` / `Modified` and the zh strings) are no longer clipped. The file panel hugs the listing instead of keeping a static 240px floor.
- **PikPak retired.** The driver is no longer offered for new mounts. Migration `0019` disables any leftover PikPak rows and keeps them delete-only.

## Upgrade and deployment

This release adds `0019_disable_pikpak_mounts.sql`. It only disables `driver_type = 'pikpak'` mounts; it does not delete files or other mount rows.

1. Pull the release and install the locked dependencies:

   ```bash
   git checkout v0.2.1
   npm ci
   ```

2. Export D1 before applying the new migration, then deploy:

   ```bash
   npx wrangler d1 export ilist-d1 --remote --output /tmp/ilist-d1-before-v0.2.1.sql
   npx wrangler d1 migrations apply ilist-d1 --remote
   npm run deploy
   ```

   Production CI applies remote migrations before `wrangler deploy`. Keep `PUBLIC_ORIGIN` exact and `CREDENTIAL_MASTER_KEY` stable.

3. After deploy, open `/admin/storages` and save mount-specific OAuth client ID/secret on each cloud drive you want independent of the Worker fallback secrets.

## Smoke test

- Create or edit an OneDrive mount, leave **Root folder ID** blank, connect, and list the drive root.
- Set a Graph folder ID as the OneDrive root and confirm listing is scoped to that folder.
- Confirm the header and page title show **iList**, the language control shows `中` (not stacked `中文`), sort labels are fully visible, and search grows left from the toolbar control.
- Confirm **PikPak** is not offered when adding storage.
